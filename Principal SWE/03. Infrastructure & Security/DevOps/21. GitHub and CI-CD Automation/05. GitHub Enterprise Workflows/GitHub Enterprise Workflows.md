## 🗂️ Core Knowledge Domains

- 📂 `01. Branch Protection Rules and Repository Rulesets` — Enforcing required PR reviews, dismissing stale approvals, requiring signed commits, linear histories, and automated Merge Queue batching.
- 📂 `02. CODEOWNERS and Automated Review Routing` — Syntax rules for `.github/CODEOWNERS`, routing domain reviews to specialized teams, required CODEOWNER approvals, and preventing unauthorized code edits.
- 📂 `03. Pull Request Templates and Issue Management` — Creating structured markdown templates (`.github/PULL_REQUEST_TEMPLATE.md`), YAML issue forms, automated issue assignment, and milestone tracking.
- 📂 [[GitHub Projects (V2), Custom Fields, and Automated Board Workflows|04. GitHub Projects and Agile Portfolio Management]] — Kanban boards, table views, custom iteration fields, automated status transitions based on PR merges, and cross-repository project tracking.
- 📂 [[GitHub Releases, Semantic Versioning (SemVer), and Auto Changelogs|05. GitHub Releases, Semantic Versioning, and Changelogs]] — Automated release notes generation from merged PR labels, publishing release assets/binaries, and managing pre-release/beta channels.
- 📂 [[GitHub Discussions, Architectural RFCs, and Collaborative Knowledge|06. GitHub Discussions, Wikis, and RFC Collaboration]] — Facilitating async technical proposals in GitHub Discussions, community Q&A categorization, converting discussions into actionable issues, and wiki docs.
