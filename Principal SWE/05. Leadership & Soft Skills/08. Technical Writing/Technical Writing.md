## 🗂️ Core Knowledge Domains

- 📂 `01. The Diataxis Documentation Framework` — Structuring documentation by user needs: Tutorials (learning-oriented), How-To Guides (task-oriented), Reference (information-oriented), and Explanation (understanding-oriented).
- 📂 `02. Docs As Code and Git Driven Documentation` — Treating documentation like software: Storing Markdown/MDX in Git, automated prose linting (Vale), building docs with Docusaurus/VitePress, and CI/CD publishing.
- 📂 [[Documenting Architectural Decisions - Lightweight ADRs and RFCs|03. Architecture Decision Records ADRs and RFCs]] — Writing concise, immutable Architecture Decision Records (Context, Decision, Consequences), integrating with code repositories, and recording technical history.
- 📂 `04. Architecture Diagrams and the C4 Model` — Creating standardized architecture diagrams: System Context, Container (apps/DBs), Component, and Code level diagrams using Structurizr and Mermaid.js.
- 📂 `05. Operational Runbooks and Standard Operating Procedures` — Writing crystal-clear operational runbooks for on-call engineers: Prerequisites, step-by-step mitigation commands, verification checks, and rollback procedures.
- 📂 [[Blameless Incident Postmortems - Comprehensive Timelines and Action Items|06. Blameless Incident Postmortems and Timelines]] — Documenting production outages: Chronological timeline, customer impact metrics, root cause analysis, what went well, what went wrong, and tracked Jira action items.
- 📂 `07. API Reference Documentation and Openapi Specs` — Generating comprehensive API reference docs from OpenAPI 3.1 specs: Documenting every field, data type, validation rule, error code, and real request/response payloads.
- 📂 [[Writing High Impact Technical Whitepapers and Architecture Deep Dives|08. Technical Whitepapers and System Design Deep Dives]] — Structuring in-depth technical whitepapers, benchmarking reports, distributed system design deep dives, and establishing company engineering authority.
- 📂 [[Translating Technical Complexity for Business Executives|09. Writing for Non Technical Stakeholders and Leadership]] — Communicating technical concepts, risks, and trade-offs to CEOs, Product VPs, and investors without jargon, using business metaphors and financial ROI models.
- 📂 [[The Art of the Executive Summary - Amazon Style 6 Page Narrative Memos|10. Executive Summaries, One Pagers, and Memos]] — Writing concise one-pagers and Amazon-style narrative memos: Framing the problem, proposing the solution, detailing the FAQ, and driving executive decisions.
- 📂 `11. Documentation Lifecycle, Deprecation, and Garbage Collection` — Preventing documentation rot: Automated links verification, doc freshness expiration tags, archiving deprecated system docs, and ownership tracking.
- 📂 `12. Maintaining Team Wikis and Obsidian Knowledge Systems` — Designing scalable team knowledge bases, taxonomies, bidirectional linking, searchable cheat sheets, and onboarding wikis for engineering organizations.
